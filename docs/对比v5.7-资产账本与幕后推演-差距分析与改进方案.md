# 资产账本 + 角色幕后推演：v5.7（主人实战体系）vs World v3.1.0 差距分析与改进方案

> 分析基准：
> - 甲方 v5.7：`C:\sly\卡\资产账本预设v11.0.json`（记账员任务）、`C:\sly\卡\[主预设] V17.1 狐神抚 · 毓忻.json`（MVU/状态栏框架）、`C:\sly\卡\酒馆助手脚本-工作流助手v0.0.17.json`（独立任务调度）、`C:\sly\SillyTavern\...\临高启明12-5 - 2026-08-10@20h58m21s.jsonl`（真实运行取证）
> - 乙方 World：`D:\World-dev\world-engine-{assets,offsight,evolution,inject,ui,core,api}.js`（v3.1.0）
> - 红线：改进不得破坏 World 架构 —— state/checkpoint/重roll/模块化/默认关闭零行为改变

---

## 一、差距分析（按严重度）

### A 级：功能缺口（v5.7 有，World 没有）

#### A1. 24h 故事时间门禁 vs 轮数门禁 —— **最核心差距**
- **v5.7**：`<LedgerTime>` 独立输出块记录 `[账目结算时间]`，记账员用 `${LedgerGapHours}`（**唯一数据依据 = 上次 LedgerTime，严禁从其它数据源推导**）判定 24h 门禁。门禁规则 1) 未满 24h → 只输出 LedgerTime、**结算时间锁定不变**、追加 `[LedgerGap] 本轮未触发结算，沿用上次账目数据`；规则 2) 满 24h 或重大结算事件 → 完整输出 `<资产账本>` 并 `[本次结算历时]=${LedgerGapHours}h` 一次性更新所有 Δ。
- **World**：`world-engine-assets.js buildPromptSection()` 用 `roundsSince = state.round - lastSettledRound` 与 `assetMajorThresholdHours`（默认 24，单位其实是**轮**）比较。故事时间流逝不均（正文一跳数日/数月）时轮数门禁完全失真。
- **关键事实**：World 的 `world-engine-core.js:592-654` **已经有故事时间解析基础设施**（`parseStoryDay`/`cnToNum`/`evolveTimeRe1-6` 设置，按时间推演模式在用），但资产门禁没有接它。`assets.ledgerTime.settledAt` 注释写明是「故事时间文本（如 澳宋-1638年-09月-02日）」却只存不读。
- **定性**：这不是能力缺失，是接线缺失。v5.7 门禁语义（故事时间 + 结算锁定 + 只更新 gate 文本）可以直接吸收。

#### A2. 记账 COT 思考流程缺失
- **v5.7**：`COT` promptGroup 有 **7 步强制思考**（Step1 门禁裁定→Step2 账本规则与逻辑→Step3 经济事件与传导→Step4 账本更新前置接收→Step5 收支计算预验证→Step6 更新必填自检→Step7 输出确认），且「不得改变、增添、减少或回避思考步数」，`<think>` 包裹、门禁文本紧跟其后。
- **World**：主推演 `DEFAULT_SEG_ENGINE_ROLE` 有通用 `<thinking>` 要求（100-300字），但资产/幕后段**没有专属思考流程**，记账质量完全靠 prompt 约束列表（约束无强制执行顺序，弱模型会跳过）。
- **定性**：v5.7 的 COT 是「质量闸门」——用思考步数强制 LLM 完成 对齐→检索→预验证→自检 的闭环。World 只给「要求」，不给「流程」。

#### A3. LedgerTime 结算锁定语义缺失
- v5.7 把「结算时间」做成**可被下轮读取的独立状态**（账目结算时间 = 上次完整结算时刻，未触发则锁定），并有「结算防重复检查」（定位上次结算对应的历史正文段，跳过已结算段落，避免事件重复计入）。
- World 的 `ledgerTime.settledAt`/`gap` 只写不读；「沿用上次账目」仅靠 prompt 文本约束，LLM 不可靠时无兜底。**防重复结算**（v5.7 COT Step1 里的时间线对齐）World 完全缺失——重roll/多轮无进展时账目可能被反复结算。

#### A4. 账目质量守则缺失（反偷懒守则 + 闭环优先守则）
- **v5.7** 输出格式 promptGroup 内置两大质量体系：
  - **反偷懒守则**：完整性硬约束（固定标题块不得省略）、建筑树点名制（资产分布出现的建筑×N 必须在生产模块有对应分支，可停工不可缺席）、最小明细配额（≥3类建筑、每类≥3项指标）、数字可追溯（汇总必须可溯源到明细）、百分比落地（基数×比率=绝对值）、"无变动"要有原因、**删减禁令**（常设条目不得静默消失，必须写拆除/战损/转移/封存/被占及后果）、常备收支对称、人员/配装/外派分层。
  - **闭环优先守则**：四点闭环（期初+流入-流出=期末，流入流出可为 0 但必须显式写 0）、收支闭环（收入/支出各≥3项明细）、自然增减资产（牲口/人口/作物）、闭环等式 Pass/Fail。
- **World**：`entries` 是扁平 `{category,name,amount,change,note,round}`，无闭环校验、无明细配额、无建筑树/人员/外派维度、无「无变动原因」要求、无 Pass/Fail。`mergeEntries` 的结构化增量合并（同名更新/新名追加）在**继承可靠性**上反而优于 v5.7（LLM 全量复制），但**单条账目质量**远不如 v5.7。

#### A5. 社交圈字段不全（缺人际网络维度）
- **v5.7 真实输出**（临高聊天第 7/11/13 条，AddonJSONPatch）：社交圈 **9 字段** = `性质 / 互动频率 / 信息范围 / 社群人脉 / 活跃角色 / 关联团体 / 关联圈交集 / 当前动态 / 描述`。「活跃角色」把角色挂到圈、「关联圈交集」把圈连成网络（丙字巷邻里圈↔元老院政务圈↔工业口生产圈），这是 v5.7 社交圈**最有价值的部分**——世界是"人-圈-组织"三层网络，不是孤立的圈子列表。
- **World**：`socialCircles` 8 字段（name/type/members/interactions/infoScope/currentActivity/description + id），**缺 活跃角色 / 关联团体 / 关联圈交集**。圈子之间无连接、角色与圈子无映射 → 幕后角色档案（offscreen.characters）与社交圈**脱节**，两套状态互不引用。

#### A6. 世界时局/产业简讯（内参日报）缺失
- **v5.7 真实输出**（第 5/7/9 条，The_Senate_status 状态栏）：完整报刊体 —— `🔔 今日头条（官方+内参核实双视角）/ 📉 产业与部委简讯（工业口/军事口/外事贸易分口）/ 🤫 百仞滩生活指南（人事动态/娱乐推荐/分类广告）/ 💬 临高BBS 热帖（带评论）`，且每轮随剧情推进更新（日产能 25→103 吨、米尼步枪 78%→82% 这种数字演进）。
- **World**：`inject.js buildContext()` 有 winds（公告/消息/流言/舆情）+ worldTrends + economy.signals，但都是**条目列表**，无报刊组织、无「官宣 vs 内参」双视角、无生活流内容。正文模型感知到的「世界时局」是数据点，不是"报纸"。

#### A7. 重大结算事件口径差异
- **v5.7**：`大额交易/开张营业/度过营业周期/战损/收购落地/迁入迁出/投资理财/获得新资产/人事调度/制度变更/灾害`，且**显式排除 `<user>` 个人资金变动不计入重大结算事件**（反偷懒守则第5条 + 门禁规则2 括号注释）。
- **World**：`MAJOR_EVENT_HINTS` = 大额交易/开张营业/营业周期/战损/收购/迁入迁出/投资理财/获得新资产/破产/融资/大额支出/产业升级。缺 人事调度/制度变更/灾害；**无个人资金排除条款** → LLM 可能把 user 买了个包子算成重大结算。

### B 级：输出质量差距（真实运行 vs World prompt 设计）

| 维度 | v5.7 实测效果 | World 现状 |
|---|---|---|
| 社交圈 | 9 字段网络化，圈与圈、圈与人有连接；当前动态与正文剧情严格同步（修缮提案表决票数 271:151:65 都进圈子动态） | 8 字段孤岛列表，与 characters 脱节 |
| 幕后角色 | 主模型输出 `<background>` 灰色日常片段（正文 1/4 篇幅）+"自动化系统"变量双轨 | offscreen.updates 只有 `第N轮 角色名：动态` 一行，注入 3 条共 1500 字符，无叙事感 |
| 世界时局 | 内参日报（头条+分口简讯+生活指南+BBS），数字逐轮演进 | winds/trends/economy 条目列表，无报刊组织 |
| 资产账本 | XML 结构化：外因/内因/流动资金多币种闭环/实体×基础设施/仓库/人员/经营/产能/运营监控，闭环等式 Pass/Fail | overview 四格文本 + 扁平 entries，无闭环校验 |
| 可读性 | 中文报刊体，直接可读可传播 | 数据点列表，注入正文后"存在感"低 |

**结论**：World 缺的不是机制（门禁/继承/合并都做了），而是**内容模板的丰富度与连接性**。机制层差距 2 项（故事时间门禁、COT），内容层差距 5 项（质量守则、社交圈网络、内参日报、重大事件口径、结算锁定语义）。

### C 级：架构差异（本质优势 vs 生态差异）

| v5.7 | World | 定性 |
|---|---|---|
| 独立任务：每次任务独立 API 调用、独立世界书选择、多 API 预设（primary+fallback+并发 5+重试 3） | 一次推演全量更新（主模型同一调用返回 assets/offscreen/socialCircles） | **本质优势**：模型专业化（记账员可用便宜/快模型，v5.7 recommendedModel=gemini-2.5-pro/gemini-3-flash-preview）、故障隔离（记账失败不影响正文） |
| 无事务：MVU 变量被 JSON Patch 原地改，无回滚 | checkpoint/重roll/存档体系，合并失败整轮回滚 | **World 本质优势**：记账随主推演原子提交，可回滚可重roll |
| 全量 XML 每次注入主上下文（worldbook depth 1 常驻） | 1500 字符摘要注入 | **World 本质优势**：token 经济 |
| 结构化变量树（时代快讯/剧情态势/经济简报/社交圈，JSON Patch 精准改字段） | 扁平 state（events/factions/winds/...） | **生态差异**：树的字段路径利于 LLM 精准 patch；World 扁平结构利于本地校验/面板/回滚。不照搬树，只吸收字段语义 |
| 回合/时间调度、messageVar 保留、副本族 | 轮次推进 + checkpoint 快照 | 生态差异，不移植 |

**架构结论**：v5.7 值得吸收的是——**故事时间门禁语义、COT 流程、质量守则、社交圈网络字段、内参日报模板、重大事件口径**；不值得照搬的是——独立变量树、MVU/JSON Patch 机制、世界书注入常驻全量 XML。独立 API 任务可作为**可选设置**引入（P1），不改变默认单调用架构。

## 二、分优先级改进方案

> 通用兼容原则（每条都遵守）：
> 1. 新增设置全部**默认关闭**或跟随现有开关（assetLedgerEnabled/offscreenEnabled）——默认路径零行为改变；
> 2. 新增 state 字段全部**可选**，`core.ensureArrays` 给默认值——旧存档加载不炸；
> 3. 合并仍走各模块 `mergeUpdate` 脏检查 + `saveStateWithLayer`——checkpoint/重roll 语义不变；
> 4. 改动局限在 assets/offsight/inject/evolution/ui 模块内部，不新增模块依赖。

### P0 —— 必须做（补核心机制，工作量小、收益最大）

#### P0-1 故事时间门禁（吸收 24h 门禁 + 结算锁定语义）
- **文件/函数**：`world-engine-assets.js` `buildPromptSection()` / `mergeUpdate()`；`world-engine-core.js` 骨架；`world-engine-ui.js` 设置。
- **改法**：
  1. `core.js` 骨架 `assets.ledgerTime` 增加 `storyDay: 0`（数字，可 null）+ `settledRound` 已有 `lastSettledRound`；
  2. `buildPromptSection()` 门禁双轨：设置 `assetGateMode`（`'rounds'` 默认 | `'story'`）。story 模式用 `core.parseStoryDay(dialogueText, settings)`（**已有函数**，从正文解析故事天数）算 `gapDays = storyDayNow - settledStoryDay`，替换现在的 `roundsSince` 判定；prompt 文本同步改为「距上次结算不足 ${threshold} 个故事日」；
  3. prompt 增加 v5.7 锁定语义原句：「未触发结算时，[账目结算时间] 锁定为上次结算时间保持不变，仅追加 [LedgerGap] 本轮未触发结算，沿用上次账目数据」；
  4. `mergeUpdate()`：API 给 `settledAt` 时用 `core.parseStoryDay` 解析并写入 `ledgerTime.storyDay`（解析不到则维持 0，回退轮数门禁）。
- **吸收 v5.7**：`${LedgerGapHours}` 唯一数据依据 + 结算时间锁定 + `[本次结算历时]` 一次更新 Δ。
- **架构保护**：默认 `'rounds'` 完全等于现状；story 模式只是把比较基准从轮换成故事日，state 只加一个可选数字字段。

#### P0-2 账目质量守则（吸收反偷懒守则 + 闭环优先守则精简版）
- **文件/函数**：`world-engine-assets.js` `buildPromptSection()`（纯 prompt 文本，零架构风险）。
- **改法**：在门禁规则后追加「记账质量守则」段（精简为 6 条，控制 token）：
  1. 数字可追溯：任何汇总数字必须在同实体明细中可溯源，不可溯源改写「待补明细」；
  2. 百分比落地：任意百分比写成 基数×比率=绝对值；
  3. 无变动要有原因：允许 Δ=0，但至少 1 个关键模块写明本期不变原因；
  4. 删减禁令：上轮已有常设条目不得静默消失；消失必须写 拆除/战损/转移/封存/被占 及后果；
  5. 闭环优先：关键科目（资金/库存/核心物资）写 期初+流入-流出=期末，可为 0 但显式写 0；
  6. 个人资金隔离：`<user>` 个人随身收支不计入账本、不算「获得新资产」。
- **UI**：`world-engine-ui.js` 设置区加 `assetQualityRules` 开关（默认开，跟随 assetLedgerEnabled 启用才生效）。

#### P0-3 重大结算事件口径补全 + 个人资金排除
- **文件/函数**：`world-engine-assets.js` `MAJOR_EVENT_HINTS`（模块常量）+ `buildPromptSection()` gateLines。
- **改法**：列表补 `人事调度、制度变更、灾害`；gateLines 追加「`<user>` 个人资金/随身物品变动不计入重大结算事件」。
- **架构保护**：纯常量 + 文本改动。

#### P0-4 社交圈网络字段（活跃角色/关联团体/关联圈交集）
- **文件/函数**：`world-engine-offsight.js` `buildPromptSection()`（输出格式）+ `mergeUpdate()`（字段解析/裁剪）；`world-engine-core.js` 骨架；`world-engine-ui.js` `renderOffsightSection()`。
- **改法**：
  1. `buildPromptSection()` 输出格式 `socialCircles` 对象加 `activeCharacters`（活跃角色）、`relatedGroups`（关联团体）、`circleLinks`（关联圈交集）三字段（数组，各上限 12/8/8，沿用现有 slice 上限风格）；
  2. `mergeUpdate()` 社交圈分支：解析三个新字段（`Array.isArray` 防御 + 逐项 slice），旧存档无字段 → 默认 `[]`；
  3. prompt 约束句：「圈子必须与幕后角色档案和关联圈子建立连接，禁止孤立圈子；已从世界消失的连接更新时移除」；
  4. `core.js` 骨架注释更新；UI 面板把 活跃角色/关联圈交集 渲染成 `→ 关联` 文本。
- **吸收 v5.7**：真实输出里 `活跃角色: 萧子山、程栋`、`关联圈交集: 丙字巷邻里圈、工业口生产圈` 这种网络化写法。
- **架构保护**：新字段全可选，默认空数组。

#### P0-5 幕后动态日志扩字段
- **文件/函数**：`world-engine-offsight.js` `buildPromptSection()` / `mergeUpdate()` / `buildContextSection()`。
- **改法**：`updates` 条目在 `{round, character, activity}` 基础上加可选 `goal/mood/location`（各 slice 40/40/100）；prompt 输出格式说明；`buildContextSection()` 注入仍只取最近 3 条、压缩为 `角色：动态` 单行——**注入体积不变**，丰富度只在面板/后台可见。
- **架构保护**：字段可选，旧数据兼容；注入格式不变。

### P1 —— 建议做（质量与体验提升）

#### P1-1 LedgerTime 结算状态可读化
- **文件/函数**：`world-engine-assets.js` `mergeUpdate()`（#7 标记逻辑扩展）；`world-engine-ui.js` `renderAssetsSection()`。
- **改法**：`ledgerTime` 增加 `lastSettledText`（结算时刻原文）+ `settledStoryDay`；未触发结算的轮次在 `ledgerTime.gap` 里记录 `第N轮未触发结算（沿用上次账目）`（v5.7 `[LedgerGap]` 文本语义）；UI 面板头部展示「账目结算时间 / 距今 N 轮 · M 个故事日」。
- **吸收 v5.7**：`[LedgerGap] 结算门禁文本` 的追溯性。
- **架构保护**：纯附加字段。

#### P1-2 记账 COT 轻量版
- **文件/函数**：`world-engine-assets.js` `buildPromptSection()` 追加「记账思考流程」段（设置 `assetCOT` 默认开，跟随总开关）。
- **改法**：v5.7 7 步 COT 精简为 **3 步强制思考**（`<thinking>` 包裹，每步一行）：
  1. 门禁裁定：本轮故事时间距上次结算多少？有无重大结算事件？执行门禁规则 1)/2)；
  2. 收支预验证：本轮每笔收入/支出是否都有 来源/去向 与数值依据？不能闭环的标「待补明细」；
  3. 自检：删减禁令/百分比落地/个人资金隔离 三条过一遍。
- **吸收 v5.7**：COT 的强制顺序（Step1 门禁→Step5 预验证→Step6 自检），砍掉 v5.7 的 20+ 项 Recall/Search 配额（token 爆炸，World 的 state 已结构化，不需要检索清单）。
- **架构保护**：纯 prompt 段。

#### P1-3 时局简报（内参日报）模板
- **文件/函数**：`world-engine-inject.js` `buildContext()`（纯模板组合，不新增 state 字段）。
- **改法**：设置 `newsDigestEnabled`（默认关）。开启时把现有数据组合成报刊体追加在 `【世界信息】` 末尾（上限 800 字符）：
