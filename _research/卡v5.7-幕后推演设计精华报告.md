## 一、体系总览：三件套分工

卡 v5.7 的幕后推演不是一个模块，而是**三个独立运行的系统**协作：

| 组件 | 职责 | 运行时机 | 产出 |
|---|---|---|---|
| 工作流助手 v0.0.17 | 独立 API 任务调度器（tavern_helper 生态） | 每次 AI 回复后，独立调 API | 结构化后台任务结果（<result> 包裹） |
| 工作流变量更新（<工作流变量更新> 块） | 增量维护世界状态树 | 每轮后台任务 | UpdateVariable + Analysis + AddonJSONPatch 三段式 |
| 自动化系统 / 资产账本 / 世界时局 | 世界活性内容（不在场角色、账目、报刊） | 每轮 | 注入主上下文的结构化/半结构化块 |

核心链路：**AI 回复 → 工作流助手独立调 API 跑后台任务 → 产出「世界后台状态」（变量树增量）+「自动化系统」（不在场角色动态）→ 通过消息变量/世界书注入主模型上下文 → 主模型在「防全知」约束下消费**。

架构本质：**独立任务 + 增量更新 + 无事务**（MVU 变量被 JSON Patch 原地改，无回滚）；与 World 的「一次推演全量更新 + 原子提交可回滚」形成两极对照（详见第八节）。

## 二、世界后台状态变量树

### 2.1 材料实证的子树结构

从 AddonJSONPatch 的 `path` 语法可确证变量树是**多级 JSON 对象路径**（RFC 6902 风格），实证到的子树：

```
/社交圈/            ← 本报告第三、四节解剖的核心子树
  /丙字巷邻里圈/
    /当前动态        ← 字段级 replace（"op":"replace","path":"/社交圈/丙字巷邻里圈/当前动态"）
    /描述
  /元老院政务圈/…
  /博铺港商运圈/…
```

其余子树（材料中的存在形态）：
- **`<资产账本/>`**：自闭合 XML 占位标签，注入点为独立账本块（对应资产账本预设 v11.0，docs A1-A4 已解剖其 24h 门禁/7 步 COT/质量守则）。
- **`<自动化系统/>`**：自闭合占位，注入不在场角色动态（第五节）。
- **`<工作流变量更新>`**：三段式容器（第三节）。

### 2.2 /临高/ 命名空间（任务背景佐证，材料未直接呈现）

据任务背景与 docs A6，根命名空间 `/临高/` 下应有：**刊报日期、时代快讯 / 世界时代阶段 / 世界时局演进动态 / 岁月史书 / 正史、世界剧情态势 / 时局动态 / 背景事件 / 当前区域事件 / 传闻、团体动态、世界经济简报**。这些分支与 `/社交圈/` 子树**同构推断**：

- 均为「目录名 → 对象 → 字段」的三级路径，字段用 `"op":"replace","path":"/临高/时局动态/当前区域事件"` 精准更新；
- 内容由「产业与部委简讯」「日程安排簿」等产出形态支撑（第七节），即**数据在聊天中生成、在变量树中沉淀**；
- 分级/分层明显：静态锚点（正史、岁月史书）vs 动态演进（时代快讯、时局动态）vs 事件级（背景事件、当前区域事件、传闻）——与 World 的 `worldTrends / winds / events` 三级粒度对应。

> ⚠️ 材料局限：上述分支的具体 JSON 形态未能从三份预处理文件中取证，吸收时以 docs A6 的「结构化变量树（时代快讯/剧情态势/经济简报/社交圈）」表述为准，字段语义比照 /社交圈/ 子树。

## 三、AddonJSONPatch 三段式增量更新（核心机制）

每轮变量更新是一个 `<工作流变量更新>` 容器，内嵌三个子块（chat_extracts 第 2-19、92-99、175-195 行实证）：

```
<工作流变量更新>
  <UpdateVariable>          ← 段1：语义标记，声明本轮为变量更新轮（触发类型）
  <Analysis>                ← 段2：LLM 决策理由链（人类可读、可审计）
  <AddonJSONPatch>          ← 段3：机器可执行的操作数组
    [ {"op":"insert","path":"/社交圈/博铺港商运圈","value":{…9字段…}},
      {"op":"replace","path":"/社交圈/丙字巷邻里圈/当前动态","value":"…"} ]
  </AddonJSONPatch>
</工作流变量更新>
```

### 3.1 三段各自的职责

1. **UpdateVariable**：标记本轮是「变量更新」而非普通正文——供提取器/注入器识别，是消息体结构化协议的一部分（与 `<资产账本/>`、`<自动化系统/>` 并列的协议标签）。
2. **Analysis**：**决策透明化层**，本设计的精华。每次更新必须交代四类操作（新增/替换/移除/合并）的完整理由链，例如：
   - 新增理由：「刘福旺作为博铺港船运商人的身份进入后台名单，且他掌握一处东门市铺面产权，与朱存炯的购买意向存在潜在因果，故需新增『博铺港商运圈』以完整呈现其社交背景。该圈子涵盖船主、货商、搬运工等码头从业人员，符合社交圈规则。」（chat_extracts 第 95 行）
   - 不建圈理由：「郑有粮作为企划院财务核算员，其工作关系并未与现有任一社交圈形成稳定重叠，故不为其新建圈子，仅通过『元老院政务圈』泛化关联。」（同段）
   - 不合并不移除理由：「经查，无废弃圈子需要移除，无重命名需求，所有更新均为对既有字段的替换。」（第 178 行）
   - 首轮全新增理由：「本轮为首次创建社交圈，因此全部为新增圈子…由于无已有社交圈，无需移除或合并。」（第 14 行）
3. **AddonJSONPatch**：RFC 6902 风格操作数组，两个 op：
   - `insert`：新增对象键（`/社交圈/博铺港商运圈`，value 为完整 9 字段对象）；
   - `replace`：替换字段值（`/社交圈/丙字巷邻里圈/当前动态`，value 为字符串；也见 `/社交圈/丙字巷邻里圈/当前动态` + `描述` 双字段整体替换，第 107 行）。

### 3.2 增量更新的设计价值

- **精准性**：path 直达字段，不改动无关数据——与 World「全量返回 + 本地合并」相比，v5.7 把「改什么」完全交给 LLM 裁量；
- **可审计性**：Analysis 与 ops 一一对应，任何状态变化都有理由记录，反推 LLM 逻辑错误（如幻觉建圈）成本极低；
- **代价**：无事务无校验，LLM 幻觉 op（错误 path/重复 insert）直接污染状态且不可回滚——这正是 World 用「全量替换 + 认领协议」换来的可靠性优势（docs C 级对比）。

## 四、社交圈模型（9 字段网络化）

### 4.1 字段表（chat_extracts 第 18-19、99、107 行实证）

| 字段 | 示例 | 维度 |
|---|---|---|
| 性质 | 地缘 / 业缘 | 分类 |
| 互动频率 | 每日街头照面，偶发串门借物 | 节奏 |
| 信息范围 | 巷内住户生活琐事、百仞城停电八卦、物资配给变动 | 情报边界 |
| 社群人脉 | 丙字巷各住户家属、勤务员 | 人脉延伸 |
| **活跃角色** | 吴明达、朱存炯 | **角色↔圈子映射** |
| 关联团体 | 元老院、中央政务院、企划院 | 圈子↔组织映射 |
| **关联圈交集** | 丙字巷邻里圈、工业口生产圈、农垦与粮食供应圈 | **圈子↔圈子网络** |
| 当前动态 | 停电后各户互相借蜡烛，电工挨户检修 | 活字段（每轮 replace） |
| 描述 | 150 字左右的地缘人文底色 | 静态锚点（慢变） |

**精华所在**：三个连接字段（活跃角色 / 关联团体 / 关联圈交集）把「孤立圈子列表」升级为**「人—圈—组织」三层网络**——角色挂在圈上、圈连成网、圈归属组织。World 的 `socialCircles` 8 字段恰好缺这三个连接字段（docs A5 已确认，P0-4 已规划补 `activeCharacters/relatedGroups/circleLinks`）。

### 4.2 圈子维护规则（从 Analysis 文本提炼的完整决策模型）

每轮维护 = **四问决策**，Analysis 必须逐一交代：

1. **新增**：新角色进入后台名单 + 与主线剧情存在**潜在因果**（刘福旺的铺面产权 ↔ 朱存炯购买意向）+ 有稳定活动场域（「符合社交圈规则」）→ 建圈；
2. **不建圈**：前台功能性归化民干部（郑有粮、赵贵）→ 不单独建圈，仅通过既有圈「泛化关联」——**控制圈数量、防止列表膨胀**；
3. **替换**：既有圈「当前动态 / 描述 / 活跃角色」随事件推进刷新（修缮提案表决票数 271:151:65 都进圈子动态，docs B 级对比）；
4. **移除/合并**：仅当「圈层崩塌或重组」时触发；正常轮次显式声明「无废弃圈子需要移除，无重命名需求」。

状态锚点：「本次社交圈推演基于 1638 年 9 月 9 日的世界状态」——每轮推演显式声明所依据的时间线快照（第 95 行），防止跨时间线混叠。

## 五、自动化系统（不在场角色动态）

### 5.1 双轨结构

docs B 级对比确认 v5.7 自动化系统是**双轨**：
- **轨 1（主模型侧）**：主预设 prompt[111]「⚙️背景npc发展」让主模型在正文中输出 `<background>` 灰色日常片段（约正文 1/4 篇幅）——叙事化、有画面；
- **轨 2（后台任务侧）**：「自动化系统」变量——结构化的不在场角色动态，由工作流助手独立任务产出。

### 5.2 后台角色池 + 每轮筛选

chat_extracts 中的「后台名单」证据（第 14、95、178 行）：吴明达、萧子山、吴南海、展无涯、冉耀、赵曼熊、刘福旺、程栋、季无声、郑有粮、赵贵、朱存炯（前台）等。机制：
- 存在一个**后台角色池**，新角色「经前文提及后进入后台名单」；
- 每轮「本轮后台角色筛选」（第 178 行）——筛选活跃者参与本轮推演，不活跃者不占 token；
- **前台功能性角色（郑有粮、赵贵）不单独建模**，只经社交圈泛化关联——与第四节的「不建圈」规则同源，是同一套「角色分级」思想。

### 5.3 不在场角色动态形态

任务背景给的形态「角色/活动/位置/目标」与 World `offscreen.characters` 的字段（`id/name/lastSeenRound/location/activity/goal/mood`，见 World 测试数据「吴明达 丙字巷 替邻居代领物资 修缮提案通过 热络」）**几乎同构**——说明两个体系在「不在场角色档案」上已经殊途同归；v5.7 的增量优势在于其动态带叙事与因果（如社交圈 Analysis 里「船主们正私下串联商议如何应对船税」），而 World 的 updates 只有一行日志（docs B 级对比 P2-2 已规划叙事化注入）。

## 六、主模型消费方式（preset_backstage.txt 解剖）

### 6.1 三个启用 prompt 的机制

全部用 `{{setvar::VAR::内容}}` 变量注入 + **命中词触发**（正则命中才启用该 prompt 段）：

| Prompt | 命中词 | setvar | 职责 |
|---|---|---|---|
| 👁️🔒 防全知/防剧透 | `不在场` | extra4 | **消费闸门**：后台状态注入后，约束模型只写角色能感知的 |
| ⬆️🎞️ 思维链（多角色内心OS） | `推演` | think1 | 输出自检：感知边界 → 内心预演 → 导演检查 |
| 🧠 思考强度：低（选一） | `推演` | think3 | 精简约束（检查项 ≤30 字结论） |

### 6.2 防全知 = 消费闸门（本设计第一精华）

后台状态是**全量注入**的（docs C 级：worldbook depth 1 常驻全量 XML），所以必须配套最强的消费约束：

- **感官边界**：视觉只写双眼所见、听觉只写双耳所闻、内在感知只写对方明确表达——「门后的景象，在推开门之前，只是未知」；
- **消息获取需有明确路径**：「不在场的事，需要有人告诉你，需要你看到留下的痕迹，需要你听到传来的声音。未经传递的信息，你不拥有」；
- **三层认知边界**：身份限定（职业阶层划定知识疆域）、时代限定（不说超时代概念）、世界限定（不引入超世界观知识）；
- 一句话纲领：「**各人活在各人的知识里，各人只知道各人的事。** 不跨域，不越界，不通晓万物，不读心！」

### 6.3 思维链的感知边界协议（think1 部分零）

把「防全知」落成可执行清单，每个在场角色逐一列出：
1. 感知范围：位置 / 视线可达 / 听觉可达 / 其他感官；
2. 合法信息来源：亲眼所见 / 亲耳所听 / 亲身经历 / 他人告知 / 合理推测（必须标注「推测」）；
3. 不可知信息（本轮绝不能知道）：他者内心秘密 / 视线外墙后之事 / 未来剧情 / 自身未经历之事 / **{{user}} 的想法和未明示行动**；
4. 正文落地：若需「猜到」，必须用「似乎/也许/感觉/总觉得/猜想」模糊词，**禁用确信语气**。

配合 think3 精简强度 + 部分一（星号/无星号交替的内心预演）+ 部分二（场景氛围/身体诚实度/潜文本/叙事技法对标/用户要求检查/反套路推翻）——形成「**后台全量注入 → 感知边界过滤 → 内心预演 → 导演级检查 → 正文**」的消费流水线。

### 6.4 状态栏保真协议（chat_extracts 第 252-258 行）

主模型正文外的自检清单，防状态坍缩：
- 时间线检查（当前时间线 1638 年 9 月，澳宋已控制两广…→ 是）；
- **防偷懒**：状态栏必须完整深拷贝，无省略；
- **防坍缩**：所有静态设定完整保留；
- 状态栏扩写：对 NPC_status 和 The_Senate_status 详细扩写；
- 状态栏审查：没有省略、没有偷懒。

> 即：世界状态注入模型后，模型在**每次生成时自证状态保真**——与 World「本地代码合并 + 校验」的可靠性来源不同（v5.7 靠 prompt 纪律，World 靠代码），可互相补位。

## 七、世界时局与经济简报的产出形态（chat_extracts 实际内容）

### 7.1 产业与部委简讯（📉 分口报刊体）

```
📉 产业与部委简讯:
  • [工业口]: 儋州洋浦化工总厂二期扩建过半，新电解槽投产；马袅钢铁厂三号高炉出铁一次成功，日产能增加25吨。博铺造船厂新启建一艘500吨级蒸汽武装商船。
  • [军事口]: 伏波军陆军换装米尼步枪进度78%，新编第二混成旅完成整训，暂驻广州大北门营区。海军第一舰队巡航台湾海峡，拦截一艘疑似葡萄牙私贩武装商船。
  • [外事/贸易]: 荷兰东印度公司巴达维亚总督府派遣使团，拟于本月下旬抵临高商谈香料贸易长期协议。澳门葡萄牙当局请求增加生丝配额。
```

**形态特征**：
- 按「口/部门」分类（工业口/军事口/外事贸易）；
- 每条 = 实体 + **量化进展**（扩建过半、+25吨/日、进度78%）+ **新事件**（拦截私贩商船）+ **未来预告**（拟于本月下旬抵临高）；
- **数字逐轮演进**（docs A6：日产能 25→103 吨、米尼步枪 78%→82%）——这是世界「活着」的可信证据。

### 7.2 日程安排簿（📅 comprehensive_now_status）

```
1638年9月-10月，海南临高特别市，百仞城
  9月20日：元老俱乐部放映《巴黎圣母院》，朱存炯携沈云蘅首次进入元老社交圈
  9月25日：荷兰东印度公司使团抵临高商谈香料贸易协议
  9月28日：旺记杂货铺租户谭广河夫妇预计开业
```

未来事件时间表，主模型据此推进时间线、后台任务据此排期（社交圈 Analysis 提到「9月13日第三次全体会议筹备会」同源）。

### 7.3 配套消费形态（同批聊天中出现的其他块）

- `<dream_plot><dream_after_format><dream_big_discuss>`：`<q content="问题">` + 多个 `<a>` 的多选分支选项（「接下来的行踪往哪边走？」3 选项）——剧情分支显式化；

## 八、工作流助手调度机制（workflow_assistant.txt 解剖）

### 8.1 顶层数据键（31 keys）→ 六大子系统

| 子系统 | 键 | 职责 |
|---|---|---|
| 任务系统 | `tasks`（每任务：名称/stage/enabled/promptGroups）、`contextTurnCount`、`memoryRecallRecentCount` | 多任务并行调度（记账员/推演/分析等各自独立任务） |
| 多 API 预设 | `apiConfig`、`apiPresets`、`defaultApiPresetName`、`activeApiPresetName`、`apiPresetBindingsByChat`、`defaultTaskApiPreset`、`taskApiPresetOverridesById` | **按任务/按聊天绑定 API 预设**：模型专业化（记账员用便宜快模型 gemini-3-flash-preview，推演用 gemini-2.5-pro）+ 故障隔离 |
| 上下文提取 | `contextExtractRules`、`contextExcludeRules` | 从对话提取任务上下文的包含/排除规则（材料中为空数组=默认态） |

### 8.2 tasks 结构（实证：「空模板任务」）

```
task: 空模板任务 | stage: 1 | enabled: True
  - [system]: 你是工作流助手。根据上下文输出简短分析，包裹在 <result> 标签内。
  - [user]: 上一用户输入：\n$8\n\n当前 AI 回复：\n$7\n\n请输出 <result>...</result>
```

- **stage**：执行阶段编号（第 1 阶段 = AI 回复后立即执行）；
- **promptGroups**：system + user 提示组，user 模板用 **`$8`（上一用户输入）/ `$7`（当前 AI 回复）** 占位符拼接上下文；
- **输出协议**：`<result>...</result>` 标签包裹 → 经 `tagVariableInjectTemplate` 转成 `<post_process_data>{{result}}</post_process_data>` 注入主上下文（世界书/消息变量）；
- **scheduleState 为空** = 默认按回合触发（每轮回复后跑一次），时间调度为可选增强；
- 真实配置的多 API 特性（primary+fallback+并发 5+重试 3）由 docs C 级对比佐证，材料中为默认空态。

### 8.3 调度设计精华

1. **回合/时间双模调度**（scheduleState + 每轮触发）；
2. **任务 × API 预设矩阵**（taskApiPresetOverridesById 按任务覆盖默认预设）——不同任务用不同模型/成本档位；
3. **任务级世界书/上下文覆盖**（taskPlotWorldbookOverridesEnabled/taskContextOverridesEnabled）——每个任务自带世界书窗口；
4. **结果注入模板化**（finalInjectTemplate/tagVariableInjectTemplate）——结果与正文解耦，可独立调整注入形态；
5. **messageVarRetention**——消息变量跨轮保留策略（后台状态持久化到消息变量，主模型经 getMessageVar 读取；材料中 getMessageVar 字样未直接出现，链路由注入模板 + docs C 级「messageVar 保留」表述佐证）。

> World 架构红线：state 对象 + 一次推演全量更新 + checkpoint/重roll + 默认关闭零行为改变。下列建议与 `docs/对比v5.7…改进方案.md` 的 P0/P1/P2 编号对齐，不重复展开实现细节。

### 🟢 A 级：直接吸收（字段/语义级，零架构风险）

1. **社交圈网络三字段**（活跃角色/关联团体/关联圈交集）→ World `socialCircles` 补 `activeCharacters/relatedGroups/circleLinks`，把「孤立圈子列表」升级为「人—圈—组织」三层网络（docs P0-4，已规划）。**本报告最高优先级吸收项**：v5.7 实测已证明网络化圈子的剧情价值（修缮提案票数都进圈子动态）。
2. **圈子维护决策模型**（新增须有「潜在因果 + 稳定场域」；前台功能性角色不建圈、泛化关联；移除/合并仅在圈层崩塌时）→ 转译为 World prompt 约束句「圈子必须与幕后角色档案和关联圈子建立连接，禁止孤立圈子；已从世界消失的连接更新时移除」+ 「无稳定重叠的角色不单独建圈」（docs P0-4 已有，补上「不建圈」条款）。
3. **后台角色池 + 每轮筛选**（新角色经前文提及入池、每轮筛活跃者）→ World `offscreen.characters` 已有 `lastSeenRound`，可加「角色池」概念：前台功能性角色显式标记不建档，控制列表膨胀。
4. **报刊体时局简报模板**（头条/分口简讯/生活指南，数字逐轮演进）→ World `inject.js buildContext()` 加 `newsDigestEnabled`（默认关），把现有 `winds/trends/economy.signals` 组合成报刊体；「官宣 vs 内参」双视角用 `winds.type=announcement/report` 自然区分（docs P1-3，已规划）。
5. **故事时间门禁语义**（`${LedgerGapHours}` 唯一数据依据 + 结算时间锁定 + `[本次结算历时]`）→ World `assets.ledgerTime` 接上已有的 `parseStoryDay` 基础设施（docs P0-1，已规划——World 已有解析器只是没接线）。

### 🟡 B 级：部分吸收（prompt/流程级，低风险）

6. **AddonJSONPatch 的 Analysis 决策理由层** → World 不全量照搬 op 机制（增量 patch 无事务，与 World 原子提交冲突），但**决策透明化**可吸收：`mergeUpdate` 后在 `updates` 日志补「新增/替换/移除 + 理由」字段，或 UI 面板展示上轮差异；`state.round` 锚点（v5.7 每轮声明「基于 X 日世界状态」）可并入 World 的 `lastEvolveResult` 展示。
7. **防全知消费闸门**（感官边界/消息获取路径/三层认知边界）→ World 注入段加「信息传播边界」提示（哪些数据角色已知/未知），特别是 winds 的传播圈层已有雏形，补一句「注入内容 = 世界事实，角色感知 = 按传播路径过滤」即得 v5.7 同款效果（docs P2-2 的叙事化注入可顺带携带边界标注）。
8. **状态栏保真自检协议**（防偷懒/防坍缩/扩写/审查四问）→ World 可作为推演输出的「本地自检清单」：面板渲染时校验静态字段是否被 LLM 全量返回（代码侧防坍缩，比 prompt 纪律更可靠）。
9. **COT 强制思考流程**（7 步精简为 3 步：门禁裁定→收支预验证→自检）→ World 主推演已有 `<thinking>`，给资产段加 3 步强制思考即得 v5.7 的「质量闸门」（docs P1-2，已规划）。
10. **重大结算事件口径**（补 人事调度/制度变更/灾害 + 显式排除 `<user>` 个人资金）→ 常量 + 文本改动（docs P0-3，已规划）。

### ⚪ C 级：不照搬（架构性差异，docs C 级对比确认）

- **独立变量树 + JSON Patch**：树的字段路径利于 LLM 精准 patch，但 World 扁平 state 利于本地校验/面板/回滚——**只吸收字段语义，不照搬树**；
- **MVU 变量原地修改（无事务）**：World 的 checkpoint/重roll 原子提交是本质优势，不可回退；
- **全量 XML 常驻注入（worldbook depth 1）**：World 的 1500 字符摘要注入是 token 经济优势；
- **独立任务多 API 调度**：可作为**可选设置**引入（docs P1-5 `assetSeparateApi`，默认关，复用 `api.js:281` 已支持的 settingsOverride），不改变默认单调用架构；
- **回合/时间调度、messageVar 保留、副本族**：生态差异，不移植。

## 十、一句话结论

卡 v5.7 的幕后推演是「**独立任务 + 增量变量树 + 注入即全知、消费靠纪律**」的 LLM 信任型架构：用 AddonJSONPatch 的精准性、Analysis 的透明性、防全知 prompt 的纪律性，换取了**叙事丰富度与连接性**（网络化社交圈、报刊体时局、双轨自动化系统）；World 引擎则是「**一次推演全量更新 + 代码合并校验 + 原子回滚**」的工程型架构，胜在可靠性与 token 经济。**两者最值得互相吸收的：World 拿 v5.7 的「内容模板与连接字段」（九节 A 级 1-5），v5.7 拿 World 的「回滚与校验」**——内容层差距 5 项、机制层差距 2 项，均已有对应 P0/P1 改进方案。
